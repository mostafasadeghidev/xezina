## لماذا Xezina؟

تحفظ مئات الصفحات ثم لا تجدها، ولكل متصفح مجموعته المختلفة من الإشارات المرجعية.
يحلّ Xezina المشكلتين معًا:

- **مجموعة واحدة من الإشارات المرجعية في كل مكان.** تبقى Chrome وEdge وBrave وOpera وVivaldi وFirefox متطابقة.
- **مكتبة يمكنك البحث فيها فعلًا.** ملاحظات ووسوم ومعاينات وبحث فوري في كل شيء.
- **لا حساب ولا خادم تابع لنا.** تبقى بياناتك في سحابتك أو خادمك الخاص.

## خيارات التخزين

| التخزين | الأنسب لـ | ما تحتاج إليه |
|---|---|---|
| **Google Drive** | الجميع | تسجيل الدخول — تُحفظ الملفات في مجلد تطبيق مخفي |
| **Dropbox** | الجميع | تسجيل الدخول — تُحفظ الملفات في `Apps/Xezina` |
| **OneDrive** | الجميع | تسجيل الدخول — تُحفظ الملفات في `Apps/Xezina` |
| **WebDAV** | Nextcloud وownCloud وSynology وQNAP وخادمك الخاص | العنوان واسم المستخدم وكلمة مرور التطبيق |
| **متوافق مع S3** | Cloudflare R2 وArvanCloud وAWS S3 وMinIO وBackblaze B2 | نقطة الاتصال (endpoint) والحاوية (bucket) ومفاتيح الوصول |
| **GitHub** | المطوّرون؛ سجلّ كامل للإصدارات | رمز وصول دقيق الصلاحيات (fine-grained token) (ينشئ Xezina مستودعًا خاصًا) |

## التثبيت

1. نزّل أحدث ملف zip من **[الإصدارات](https://github.com/mostafasadeghidev/xezina/releases/latest)**.
2. **Chrome وEdge وBrave وOpera وVivaldi:** فكّ ضغط `xezina-*-chrome.zip` ← افتح `chrome://extensions`
   (`edge://extensions` في Edge) ← فعّل **Developer mode** (وضع المطوّر) ← **Load unpacked** (تحميل غير المضغوط) ← اختر المجلد الذي فككت ضغطه.
3. **Firefox:** استخدم `xezina-*-firefox.zip`. ستُنشر نسخة موقّعة على addons.mozilla.org.

أبقِ المجلد المفكوك في مكانه: يحمّل المتصفح الإضافة منه.

## البدء السريع

1. افتح Xezina بالضغط على <kbd>Alt</kbd>+<kbd>Shift</kbd>+<kbd>B</kbd>، أو انقر أيقونة شريط الأدوات ← زر الشبكة.
2. انتقل إلى **الإعدادات ← المزامنة**، واختر وسيلة تخزين واتصل بها.
3. ثبّت Xezina في متصفحاتك الأخرى واربطها **بوسيلة التخزين نفسها**.
   إذا كنت تستخدم التشفير، فأدخل عبارة المرور نفسها.
4. انتهى الأمر. تظهر إشاراتك المرجعية في شريط الإشارات المرجعية وقائمتها في كل متصفح. افتح مدير Xezina
   فقط عندما تريد البحث أو كتابة الملاحظات أو الترتيب.

> [!TIP]
> أوقف مزامنة الإشارات المرجعية الخاصة بالمتصفح (مزامنة الإشارات المرجعية في Chrome Sync، ومزامنة المفضلة في Edge) على
> الأجهزة التي يزامن فيها Xezina، حتى لا يعدّل نظامان الإشارات المرجعية نفسها.

> [!NOTE]
> عند اتصال المتصفح لأول مرة، تُطابَق الإشارات المرجعية التي يشترك فيها مع المتصفحات الأخرى (المجلد نفسه
> والعنوان نفسه) بدلًا من تكرارها. أما إذا أردت أن يطابق المتصفح النسخة السحابية **تمامًا**،
> فاستخدم **الإعدادات ← المزامنة ← اجعل هذا المتصفح مطابقًا للسحابة** مرة واحدة. تُنشأ نسخة احتياطية أولًا.

## الأسئلة الشائعة

<details>
<summary><b>هل يرى Xezina إشاراتي المرجعية أو تصفّحي؟</b></summary>

لا. لا يوجد خادم لـ Xezina. ينتقل كل شيء مباشرة من متصفحك إلى وسيلة التخزين التي
اخترتها. لا تُقرأ الصفحات إلا إذا سمحت بالمعاينات، ولا يُقرأ إلا ما حفظته في الإشارات المرجعية.
</details>

<details>
<summary><b>ماذا يحدث إذا عدّلت الإشارة المرجعية نفسها في متصفحين؟</b></summary>

يُدمج كل حقل (العنوان، والرابط، والمجلد، والموضع، والملاحظات، والوسوم) على حدة، ويفوز أحدث
تغيير على ذلك الحقل. وتُحفظ التغييرات المختلفة على الإشارة المرجعية نفسها كلها.
</details>

<details>
<summary><b>ماذا لو حدث خطأ أثناء المزامنة؟</b></summary>

ينشئ Xezina نسخة احتياطية قبل كل مزامنة تغيّر إشاراتك المرجعية. يمكنك استعادة أيٍّ من آخر 30
نسخة احتياطية من **الإعدادات ← النسخ الاحتياطية والبيانات**. وأي مزامنة قد تحذف عددًا كبيرًا من الإشارات المرجعية تنتظر
تأكيدك.
</details>

<details>
<summary><b>تسجيل الدخول إلى Google Drive / Dropbox / OneDrive يقول إن التطبيق غير مُهيّأ.</b></summary>

تحتاج هذه الخدمات إلى تسجيل تطبيق لمرة واحدة من قِبل من ينشر النسخة المبنية. راجع
[docs/oauth-setup.md](../oauth-setup.md). أما WebDAV وS3 وGitHub فتعمل من دونه.
</details>

<details>
<summary><b>هل يمكنني تصدير إشاراتي المرجعية؟</b></summary>

نعم. يمكنك التصدير إلى HTML القياسي (يمكن استيراده في أي متصفح) أو JSON (مع الملاحظات والوسوم)،
واستيراد ملفات HTML، من **الإعدادات ← النسخ الاحتياطية والبيانات**.
</details>

## كيف تعمل المزامنة

كل إشارة مرجعية هي سجلّ يحمل كل حقل من حقوله طابعًا زمنيًا من ساعة منطقية هجينة (hybrid logical clock). يرفع كل جهاز
نسخته المدمجة الكاملة في ملف واحد (`devices/<id>.xz`) ويقرأ ملفات الأجهزة الأخرى.
يأخذ الدمج أحدث قيمة لكل حقل، لذا تكون النتيجة واحدة أيًّا كان ترتيب وصول
الملفات (CRDT قائم على الحالة). ولأن كل جهاز يكتب ملفه فقط، تصلح أي وسيلة تخزين ملفات عادية،
ولا يمكن لجهازين أن يكتب أحدهما فوق الآخر أبدًا. تُحفظ العناصر المحذوفة كشواهد حذف (tombstones)؛ والمجلد المحذوف على جهاز
الذي تُضاف إليه إشارة مرجعية جديدة على جهاز آخر يعود مع تلك الإشارة. وتُستخدم الفهرسة الكسرية (fractional indexing) لترتيب العناصر داخل المجلدات.

## التطوير

```bash
pnpm install
pnpm dev                 # Chrome with live reload  (pnpm dev:firefox for Firefox)
pnpm test                # unit tests + randomized multi-browser sync simulations
pnpm build && node scripts/e2e.mjs        # two real Edge profiles syncing over WebDAV
pnpm build && node scripts/screenshots.mjs  # regenerate docs/screenshots
pnpm zip && pnpm zip:firefox
```

| المجلد | المحتوى |
|---|---|
| `src/core` | نموذج البيانات، ودمج CRDT، والترتيب، والبحث |
| `src/sync` | قراءة الإشارات المرجعية للمتصفح وتطبيقها، والمطابقة عند الاتصال الأول، والتشفير |
| `src/storage` | محوّل صغير لكل مزوّد تخزين |
| `src/background` | المجدوِل، والمعاينات، وفاحص الروابط |
| `src/ui` | المدير، والنافذة المنبثقة، والترجمات (`src/ui/i18n`) |
| `docs` | الموقع (GitHub Pages)، ولقطات الشاشة، وملفات README المترجمة |

**تطبيقات تسجيل الدخول:** تحتاج Google Drive وDropbox وOneDrive و"Sign in with GitHub" إلى معرّفات عملاء OAuth (client ids)،
تُقرأ وقت البناء من `.env` (راجع `.env.example`) أو يُدخلها المستخدمون في
**الإعدادات ← متقدم**. دليل خطوة بخطوة: [docs/oauth-setup.md](../oauth-setup.md).

**الترجمات:** توجد نصوص الواجهة في `src/ui/i18n/<lang>.ts`، ونصوص الموقع في
`docs/i18n/<lang>.js`. نرحّب كثيرًا بتصحيحات الناطقين الأصليين.
